Team Configuration

Customize PenguinCAM for your team's specific CNC machines with a PenguinCAM-config.yaml file. The same file works two ways: Onshape users keep it in their Onshape documents, and everyone else hosts it at a URL and points PenguinCAM at it. The format is identical — only how PenguinCAM finds it differs.

ℹ️
Without a config file: PenguinCAM uses Team 6238's default settings (24"×24" machine, conservative feed rates). These work but may not be optimal for your machine.

How PenguinCAM Finds Your Config

The config format is the same everywhere; only how PenguinCAM loads it depends on how you use the app:

  • In Onshape: keep PenguinCAM-config.yaml in your Onshape documents. When you authenticate, PenguinCAM loads it automatically. (See Onshape Setup.)
  • Direct upload (no Onshape): host the file at a public URL and point PenguinCAM at it — either by pasting the URL into the Setup screen or by adding a ?config= parameter to the app link. (See Hosting Your Config at a URL.)

Onshape Setup

1

Download Template

Download PenguinCAM-config-template.yaml

2

Edit for Your Machine

Open in a text editor and customize machine dimensions, feed rates, and materials. See detailed configuration options below.

3

Upload to Onshape

In Onshape, create a new document or use an existing one. Click the + icon and upload your config file. Name it exactly PenguinCAM-config.yaml (case sensitive).

4

Share with Your Team

Share the Onshape document with your team members or classroom, so that everyone can access the settings. Everyone who authenticates with PenguinCAM from your organization will load and use your custom settings.

Hosting Your Config at a URL

If you don't use Onshape (you upload DXF files directly), host your PenguinCAM-config.yaml somewhere your browser can fetch it, then point PenguinCAM at that URL. Your whole team can then share a single link.

⚠️
Host it on GitHub or a gist — not Google Drive or Dropbox. Your browser fetches the file directly, so the host has to allow cross-origin requests (CORS). GitHub's raw file URLs and gists do; Google Drive and Dropbox share links do not, so those won't load. (This browser-side fetch is also why your config URL never touches our server.)
1

Host the File

Commit PenguinCAM-config.yaml to a public GitHub repository, or put it in a gist if it's just the one file. Keeping it in Git also gives you edit history and an easy way to share updates with your team.

2

Copy the Raw URL

Open the file on GitHub and click Raw, then copy the address. It looks like: 

https://raw.githubusercontent.com/YOUR-TEAM/YOUR-REPO/main/PenguinCAM-config.yaml

The raw.githubusercontent.com host is the important part — a normal github.com/.../blob/... page URL is an HTML page, not the file itself, and won't load.

3

Load It in PenguinCAM

On the Setup screen, paste the URL into the Team configuration field and click Load. PenguinCAM fetches and validates it, shows the team it parsed (e.g. Loaded config for team 1234), and remembers it in your browser for next time.

4

Share the Link with Your Team

Once you load a URL, PenguinCAM adds it to the page address as a ?config= parameter (properly encoded). Bookmark or share that address and anyone who opens it loads the same config automatically: 

https://penguincam.popcornpenguins.com/?config=https://raw.githubusercontent.com/YOUR-TEAM/YOUR-REPO/main/PenguinCAM-config.yaml
ℹ️
Editing later: PenguinCAM re-fetches the file from the URL each visit, so you (or a teammate) can update the hosted config and everyone picks up the change next time they open the app — nothing to re-enter. To go back to the built-in defaults, click Use defaults on the Setup screen.

Configuration Structure

📏
Units: Dimension values default to inches, but you can add a unit to any dimension — quote it so YAML reads it as text: diameter: "4mm", x_max: "1200mm", width: "0.25in", or a fraction like "1/8". Supported units: in/", mm, cm, m, ft/', yd. A plain number (no unit) is inches. Non-dimension values (feed rates, RPM, angles, ratios) are always plain numbers.

Team Information

Identify your team. This appears in logs and helps us provide support: 

team:
  number: 1234
  name: "Your Team Name"

Machine Definitions

Define one or more CNC machines. If you have multiple machines (e.g., a smaller one for prototyping), you can configure each with different settings: 

machines:
  main_cnc:
    name: "Omio X8-2200"

    machine:
      dimensions:
        x_max: 22.2    # Work envelope in inches
        y_max: 30.3
        z_max: 3.3
Setting Description Default
x_max Maximum X travel (inches) 48.0
y_max Maximum Y travel (inches) 96.0
z_max Maximum Z travel (inches) 3.3

Park Position (Machine Coordinates) — optional

Optionally park the gantry at a fixed machine location at the end of a program for easy part access. This uses G53 machine coordinates, and it is the only thing that puts G53 in the output: 

park_position:
  x: 0.5       # X position in machine coords
  y: 0.5       # Y position in machine coords
  z: -0.5      # safe machine Z to raise to before parking
⚠️
Leave this out for GRBL / Easel and other non-G53 controllers. Without park_position, PenguinCAM emits portable, G54 work-coordinate only G-code (start and end retracts use a work-coordinate safe height, no G53). If a machine plunges at the origin or mishandles the safe move, remove this block. Everything else works the same.

Coolant — optional

Optionally emit coolant M-codes. Omit it (or set None) and no coolant commands are written — recommended for controllers that don't support them (stock GRBL rejects M7 unless compiled with it). 

machine:
  coolant: "Air"   # Air/Mist -> M7 (e.g. air blast), Flood -> M8, off -> M9; None/omit -> nothing

Default Tool

Set the default tool diameter that appears when loading a new part. You can specify it in metric or inches (see the Units note above); it's shown in the UI exactly as written. If omitted, the default is 4mm. 

default_tool:
  diameter: "4mm"    # or "1/8", or a plain number in inches (0.157)

Z-Axis Reference System

Z=0 is the top of the sacrifice board (the bottom of your stock); the stock top sits at Z = material thickness. Configure how deep to cut and how high to clear: 

z_reference:
  sacrifice_board_depth: 0.008    # How far to cut into the sacrifice board (through-cuts)
  clearance_height: 0.5           # Clearance above the stock for in-part rapids
  safe_height: 2.0                # OPTIONAL: "clear everything" height (see below)

clearance_height is the small hop above the stock used for rapids between features within a part (these stay over the stock, so they only need to clear it).

safe_height is optional and is the "clear everything" height (work coordinates, over Z=0) used only for the moves that cross the machine bed: the rapid to the first cut, the final retract, multi-part rapids, and the tube-flip pause. Set it above your tallest clamp or fixture so those moves clear it. If you omit it, those moves fall back to material thickness + clearance_height (just above the stock) — fine for low edge clamps, but it will not clear tall fixturing. (This replaces the old machine-coordinate G53 retract, which is now opt-in via park_position.)

Material Presets

Define materials with appropriate feed rates and speeds for your machine's rigidity: 

materials:
  plywood:
    name: "Plywood"
    feed_rate: 60.0              # Cutting feed rate (IPM)
    ramp_feed_rate: 40.0         # Feed rate for ramping into material
    plunge_rate: 15.0            # Plunge feed rate
    ramp_start_clearance: 0.05   # Clearance before ramping
    ramp_angle: 4.0              # Ramp angle (degrees)
    stepover_fraction: 0.25      # Stepover as fraction of tool diameter
Material Typical Feed Rate Notes
Plywood 50-80 IPM Fast cutting, watch for tear-out on edges
Aluminum 40-60 IPM Use flood coolant if available
Polycarbonate 30-50 IPM Slower speeds to avoid melting
HDPE 40-60 IPM Sharp tools required to avoid smearing
⚠️
Important: Start with conservative feed rates and increase gradually. Pushing too hard can damage tools or your machine. Always run test cuts on scrap material first.

Corner Feed Slowdown — optional

When clearing a pocket, the cutter takes a light bite (the stepover) along a straight edge, but at a sharp interior corner it wraps around two edges at once and its engagement — and cutting force — spikes. To tame that, PenguinCAM eases the feed rate down within a tool-diameter of each sharp corner and ramps it back up on the straights. The toolpath geometry is unchanged — only the feed changes near corners.

How much to slow is a per-material setting, corner_min_feed_scale (a fraction of the material's feed_rate, applied at the sharpest corners): 

materials:
  aluminum:
    corner_min_feed_scale: 0.4    # aggressive slowdown
  polycarbonate:
    corner_min_feed_scale: 0.7    # gentler slowdown

The right value depends on what limits the material. Aluminum is force-limited — a sharp corner can deflect or break the tool — so an aggressive floor (0.4, i.e. 40% of feed) is worthwhile. Softer, heat-sensitive materials like polycarbonate and plywood are low-force but rubbing-limited: cutting the feed too far drops the chip load and the tool starts rubbing instead of cutting, which builds heat (and melts plastics). Those use a gentler floor (0.7) to keep the chips shearing. Omit the setting to use PenguinCAM's built-in per-material default (0.4 for aluminum, 0.7 for softer materials); set it to 1.0 to disable corner slowdown for that material entirely.

Tab Settings

Configure how parts are secured during perimeter cutting. Two strategies are available: 

tabs:
  enabled: true     # Use automatic tabs (they're removed at the end)
  width: 0.25       # Tab width (inches)
  height: 0.15      # How much material left in tab

fixturing:
  pause_before_perimeter: false  # If true, skip tabs and pause for manual fixturing

Choose one strategy:

  • Automatic tabs (enabled: true): Tabs are placed automatically and removed as the final step. No manual intervention needed.
  • Pause for fixturing (pause_before_perimeter: true): No tabs are placed. Program pauses (M0) before perimeter cut to allow fixturing through milled holes.

Multiple Machines

If your team has multiple CNCs, define each in the config: 

version: 2
default_machine: main_cnc

machines:
  main_cnc:
    name: "Main CNC (Omio X8)"
    machine:
      dimensions:
        x_max: 22.2
        y_max: 30.3
    materials:
      plywood:
        feed_rate: 60.0

  prototype_cnc:
    name: "Prototype CNC (Smaller)"
    machine:
      dimensions:
        x_max: 12.0
        y_max: 12.0
    materials:
      plywood:
        feed_rate: 40.0    # Slower for less rigid machine

Users can select which machine to use from the UI dropdown (if more than one is configured).

Google Drive Integration

To enable automatic uploads to Google Drive, configure your Drive folder ID: 

google_drive:
  enabled: true
  folder_id: "your-folder-id-here"
  folder_name: "CNC Programs"

To find your folder ID:

  1. Open Google Drive and navigate to the folder where you want programs saved
  2. Copy the folder ID from the URL:
    https://drive.google.com/drive/folders/ABC123xyz
  3. Paste the ID into your config file
ℹ️
Note: Drive integration requires your team to be in a Google Workspace organization. Personal Gmail accounts are not currently supported for Drive uploads.

Advanced Settings

Hole Detection

Control how PenguinCAM detects and machines holes: 

holes:
  detection_tolerance: 0.0001         # Circularity tolerance
  min_millable_multiplier: 1.2        # Min hole = 1.2× tool diameter

Pocket and Hole Contouring

For large through-cut features, PenguinCAM can contour the perimeter instead of fully clearing the interior. This saves significant machining time, with the trade-off that the center material must be removed manually afterward (it's held in place by tabs). 

pockets:
  contour_threshold: 510    # Area threshold for contouring

The threshold determines when a feature is large enough to benefit from contouring. The formula is: 

threshold_area = contour_threshold × tool_diameter² × stepover_percentage

This means tighter stepover (aluminum) has a lower threshold and will contour smaller features, since those features take many more passes to clear. With the default threshold of 510:

  • Aluminum (25% stepover): Contours features larger than ~2.0" diameter
  • Plywood (65% stepover): Contours features larger than ~3.2" diameter
  • Polycarbonate (55% stepover): Contours features larger than ~3.0" diameter
ℹ️
Important: Contouring only applies to through-cuts (features that go all the way through the material to Z=0). Partial-depth features are always fully cleared since they need flat bottoms for functionality. Set contour_threshold: 0 to disable contouring entirely.

Tube Facing

For teams that machine aluminum tube, configure tube-specific parameters: 

tube_facing:
  depth_margin: 0.005               # Extra depth beyond half-height
  max_roughing_depth: 0.3           # Roughing pass depth
  max_finishing_depth: 0.51         # Finishing pass depth

Version 1 vs Version 2

PenguinCAM supports two config formats:

Version 1 (Legacy)

Single machine, flat structure. Still supported for backwards compatibility: 

# No version field = Version 1
team_number: 1234
team_name: "Your Team"
machine_x_max: 24.0
machine_y_max: 24.0

Version 2 (Current)

Multiple machines, nested structure. Recommended for new configs: 

version: 2
default_machine: main_cnc
machines:
  main_cnc:
    name: "Main CNC"
    ...

If you have an old Version 1 config, it will continue to work. Upgrade to Version 2 to support multiple machines or per-machine material settings.

Validation

When PenguinCAM loads your config, it will:

  • Use your custom values where provided
  • Fall back to Team 6238 defaults for any missing values
  • Display warnings in the UI if materials are incomplete

Check the browser console (F12) after authenticating to see which config was loaded: 

✅ Team config loaded: Your Team Name (#1234)

The same checks run whether the config comes from Onshape or a URL. Text values (names and descriptions) are also sanitized to be CNC-safe — parentheses and non-ASCII characters (curly quotes, arrows, the degree symbol, etc.) are removed, because they can end up in G-code comments and break some controllers. If PenguinCAM adjusts anything, it tells you what it changed; your machine settings themselves are unaffected.

Troubleshooting

Config not loading

If PenguinCAM shows "Using default configuration" instead of your config, first click the small ↻ reload glyph next to that message. PenguinCAM caches the result of its config search for 10 minutes, so a config you just added won't appear until the cache expires — the glyph searches again immediately and then tells you what it found, or why it found nothing. It is available whether or not a config is currently loaded.

If it still reports nothing:

  • Verify the filename is exactly PenguinCAM-config.yaml (case sensitive). The tab holding the YAML must carry that name, not just the document.
  • The document must be owned by an Onshape classroom or company you belong to — a config in a personal document is never picked up.
  • Onshape's search index can take a few minutes to notice a brand-new file, so a config created seconds ago may simply not be findable yet. Wait a moment and click the reload glyph again.
  • Check that the document is shared with your team/organization in Onshape
  • Verify the document is shared with the PenguinCAM app (use "Share with applications" tab in Onshape sharing dialog)
  • Ensure you're authenticated with Onshape (click the login button)
  • Verify the file is valid YAML (use a YAML validator online)

Config URL won't load

If pasting a URL (or opening a ?config= link) shows a fetch or CORS error:

  • Make sure you're using a raw URL (raw.githubusercontent.com/...), not a github.com page URL.
  • Google Drive and Dropbox links won't work — they don't let the browser fetch the file directly (CORS). Host it on GitHub or a gist instead.
  • Confirm the URL is public and opens the raw YAML directly when you paste it into a browser tab.
  • A "rejected" message means the file loaded but failed validation — check that it's valid YAML and that values are in range (the message says what's wrong).

Material shows warning

If you see "⚠️ This material has incomplete settings", it means your config defines the material but is missing some required parameters (feed rate, plunge rate, etc.). The missing values will use plywood defaults.

Multiple teams see the same config

This can happen if your config file is shared publicly. PenguinCAM now filters configs by ownership:

  • Only configs owned by your company/organization are used
  • If you see someone else's config, verify your file is in your company's Onshape documents
  • Don't share your config file publicly - keep it in your team/company folder
